WitDiff: deterministic verification for AI-written code
======================================================

The maintained version of this snippet lives at
`integrations/generic/AGENTS.md`, alongside installable packages for Claude
Code, OpenCode, Pi and Cursor. That file adds the status table and the
exit-code rules; this one is kept because older checkouts link to it.

Run `integrations/install.sh` to set up the harness you use.

--- BEGIN INSTRUCTION SNIPPET ---

Before claiming that a code change is complete or verified, run:

    witdiff verify --base origin/main --strict --json

Read the exit code as three distinct signals, not two:

    0   the claim was proven, or there was nothing to prove
    1   WitDiff itself failed to run - a tool error, not a verification result
    2   verification did not pass

Exit code 2 is a failed verification gate. It is not a crash, and it is not a
reason to retry. Do not report a change as complete while it exits 2.

Exit code 0 is not by itself proof. Check the `status` field in the receipt:

    verified                 the base experiment failed for a test reason and
                             passes on the workspace: the claim is proven
    verified_with_warnings   proven, with integrity findings; read them
    no_changed_tests         nothing was proven, because no test changed.
                             This is not a pass and not a failure.
    not_verified             a proof was attempted and did not establish the
                             claim, or the change was undecidable
    head_failed              the workspace's own tests fail; fix them first
    base_incompatible        the transplanted test could not compile against
                             the base revision, so no behavioral proof was
                             established. Separate the change and its test.

Rules for reporting results:

- Quote the receipt's `status` and the integrity findings. Do not summarize
  them as "tests pass".
- Never rewrite, suppress, or reinterpret a failed WitDiff result.
- If WitDiff reports an unsupported case - inline tests it declined to splice, a
  path whose encoding is lossy, a base revision that did not parse - state that
  limitation explicitly in your report. An unsupported case is not a pass.
- If the workspace changed while verification ran, `evidence_fresh` is false and
  the evidence is stale. Re-run; do not cite the stale receipt.

When WitDiff reports `no_changed_tests`, say so plainly: there is no proof,
because nothing was proven. Do not present it as success.

Useful additions:

- `witdiff verify --base <ref> --github-annotations` emits GitHub Actions
  annotations for the status and every finding.
- `witdiff inspect --base <ref>` shows how files were classified before running
  anything, which is the fastest way to diagnose a surprising status.
- `witdiff receipt --json` prints the last receipt without re-running.

--- END INSTRUCTION SNIPPET ---


Why the instructions are shaped this way
----------------------------------------

WitDiff exists because an agent asserting "the tests pass" is not evidence. The
snippet keeps that boundary: the agent's job is to run a deterministic tool and
report what it said, including what it could not determine. The three-way exit
code matters because "nothing to prove" and "the proof failed" are different
facts, and collapsing them either fails correct changes or passes unproven ones.

See docs/verification-model.md for what each status means in detail, and
docs/agents.md for guidance on working on WitDiff itself.
